# Security Policy

## BLACKVEIL X Security Policy

The security of BLACKVEIL X and its users is important to us. We take security vulnerabilities seriously and appreciate responsible security research and disclosure.

## Supported Versions

Security updates are primarily focused on the latest available release.

| Version | Security Support |
|---|---|
| Latest Release | Supported |
| Older Releases | Not guaranteed |

## Reporting a Vulnerability

If you discover a potential security vulnerability in BLACKVEIL X, please report it responsibly.

**Please do not disclose security vulnerabilities publicly before they have been investigated.**

When reporting a vulnerability, include:

- A clear description of the vulnerability.
- Steps required to reproduce the issue.
- Potential security impact.
- A proof of concept, if available.
- Affected modules or components.
- Suggested mitigation, if known.

### How to Report

Use GitHub's private vulnerability reporting feature if it is enabled for this repository.

Repository:
https://github.com/7k9lrez/blackveil

If private vulnerability reporting is unavailable, contact the maintainer through their GitHub profile.

## Scope

The following components are within the intended security review scope:

- BLACKVEIL X core architecture.
- Python modules and internal components.
- Authentication and authorization mechanisms, where applicable.
- Docker sandbox integration.
- Input validation and command execution.
- File handling and report generation.
- API integrations and configuration handling.
- Dependency security issues that directly affect BLACKVEIL X.

## Out of Scope

The following activities are not authorized by this policy:

- Testing systems or infrastructure belonging to third parties.
- Unauthorized access to external services.
- Denial-of-service attacks.
- Social engineering or phishing.
- Accessing, modifying, or exposing other users' data.
- Testing outside systems without explicit authorization.

All security testing must be conducted against systems you own or have explicit permission to test.

## Responsible Disclosure Guidelines

We ask security researchers to:

1. Act in good faith.
2. Avoid accessing or modifying data that does not belong to them.
3. Avoid disrupting services or damaging systems.
4. Provide sufficient technical details to reproduce findings.
5. Allow maintainers reasonable time to investigate and address reported issues.
6. Avoid publishing exploit details before coordinated disclosure.

## Security Updates

Security fixes and relevant improvements may be published through GitHub commits, releases, and security advisories.

Users are encouraged to keep their installations updated.

## Disclaimer

BLACKVEIL X is a cybersecurity framework intended for authorized security research, educational purposes, and defensive security testing.

Users are responsible for ensuring that their activities comply with applicable laws and regulations.

Unauthorized use of security tools against systems without permission is not supported or endorsed.
